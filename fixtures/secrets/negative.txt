#
# Precision corpus for the certain-secret patterns of patterns/certain-secrets.v1.json.
# The whole file, comment lines included, must produce zero matches: a single hit here is
# a false positive that would redact ordinary text in a preview or mask a spec value the
# user needs. It holds the text a dashboard, a terminal and a chat actually produce, the
# identifiers this project generates, and the near misses each pattern is most likely to
# trip on: right prefix and wrong length, right length and wrong case, right shape and
# wrong separator.

## Tokens, sessions and authentication in prose

The access token is a JWT; the refresh token is an opaque string.
A JWT has three base64url segments separated by dots: header, payload, signature.
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9 on its own is only a header, not a token.
Decoding a JWT is not verifying it: the signature check is the part that matters.
Bearer authentication puts the credential in the Authorization header.
The session cookie is HttpOnly, Secure and SameSite=Lax.
Access tokens live 15 minutes, refresh tokens 30 days, both rotated on use.
Never log the Authorization header, not even at debug level.
The channel token is 32 random bytes stored as 64 lowercase hexadecimal characters.
mTLS was considered and rejected: the peers are on the same machine as the same user.
OIDC discovery is at /.well-known/openid-configuration on the issuer.
Introspection returns active=false once the token has been revoked.
